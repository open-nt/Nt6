Detailed Description

A QRecursiveMutex can be locked repeatedly by the thread that already owns it. Each call to lock() or a successful tryLock() must be paired with a call to unlock(); the mutex is released for other threads when the lock count returns to zero.

See also QMutex and QMutexLocker.

Differences from Qt

QRecursiveMutex wraps std::recursive_timed_mutex. It has no try_lock() or isRecursive(). A negative timeout passed to tryLock() is treated as 0 rather than waiting forever.

Member Function Documentation

QRecursiveMutex::QRecursiveMutex()

Constructs an unlocked recursive mutex.

void QRecursiveMutex::lock()

Locks the mutex. If another thread holds the lock, this call blocks until the mutex becomes available. A thread that already owns the mutex may call lock() again.

See also unlock() and tryLock().

bool QRecursiveMutex::tryLock(int timeoutMs = 0)

Attempts to lock the mutex, waiting up to timeoutMs milliseconds for it to become available. Returns true if the lock was obtained; otherwise returns false.

If timeoutMs is 0 or negative, the call returns immediately.

See also lock() and unlock().

void QRecursiveMutex::unlock()

Unlocks the mutex once. The calling thread must own the mutex.

See also lock().
