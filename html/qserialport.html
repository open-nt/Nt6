Detailed Description

Name the port, open it, then read and write as with any QIODevice. Settings made before open() take effect when the port opens; settings made later take effect at once.

QSerialPort port("ttyUSB0");
port.setBaudRate(QSerialPort::Baud115200);
if (!port.open(QIODevice::ReadWrite)) {
    qWarning() << port.errorString();
    return;
}
QObject::connect(&port, &QIODevice::readyRead, [&] { handle(port.readAll()); });
port.write("AT\r\n");

A new port is set to 9600 baud, 8 data bits, no parity, one stop bit and no flow control. Whatever the device was set to before is restored by close().

Reads and writes do not block. Data moves while the event loop runs, or inside waitForReadyRead() and waitForBytesWritten() in a program without an event loop.

A port is opened exclusively. Opening a port that another QSerialPort has open fails with PermissionError, in this process or any other.

When the device goes away, for example when a USB adapter is unplugged, errorOccurred() is emitted with ResourceError. The port then stays open but idle, and data received earlier can still be read. Call close(), and open() again once the device is back.

See also QSerialPortInfo.

Differences from Qt

Bytes received with a parity or framing error are dropped. OneAndHalfStop is not available, because POSIX has no such setting; it makes open() or setStopBits() fail. errorOccurred() is not emitted for NoError, which Qt does when an error is cleared. There are no bindable properties. waitForBytesWritten() waits for the whole buffer, not for one chunk of it. Exclusive access uses flock() and TIOCEXCL rather than a lock file in /var/lock. Ports are POSIX terminal devices; only Linux has been tested.

bool QSerialPort::setBaudRate(qint32 baudRate, Directions directions = AllDirections)

Sets the baud rate to baudRate for the given directions. Returns true if successful.

Any positive rate is accepted, and a rate that is not among QSerialPortInfo::standardBaudRates() is passed to the driver as it is. If the port is open and the driver or the system refuses it, the function returns false; if the port is closed, open() does. Most hardware needs the same rate in both directions.

See also baudRate().

[override] bool QSerialPort::waitForBytesWritten(int msecs = 30000)

Reimplements QIODevice::waitForBytesWritten().

Waits up to msecs milliseconds until the whole write buffer has been passed to the driver, doing the work of the event loop meanwhile. A negative value waits forever. Returns true if it has, and false if there was nothing to write. A timeout sets TimeoutError.

The driver sends the data at its own pace, so it may not have left the machine yet.

See also bytesWritten(), waitForReadyRead() and flush().

[override] bool QSerialPort::waitForReadyRead(int msecs = 30000)

Reimplements QIODevice::waitForReadyRead().

Waits up to msecs milliseconds for new data, doing the work of the event loop meanwhile. A negative value waits forever. Returns true if data arrived, or if the read buffer is already full. A timeout sets TimeoutError.

See also readyRead() and waitForBytesWritten().
