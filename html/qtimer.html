Detailed Description

A QTimer emits timeout() each time its interval elapses. Connect that signal to whatever should run, then call start():

QTimer timer;
QObject::connect(&timer, &QTimer::timeout, [] { poll(); });
timer.start(250);

Timers run on the event loop, so timeout() is only emitted while a QCoreApplication or QEventLoop is executing. An interval is a minimum delay, not a guarantee: a busy loop delivers the signal late.

A timer normally repeats until stop() is called. Call setSingleShot(true) to have it fire once, or use the static singleShot() functions when no timer object is needed.

See also Signals and Slots.

Differences from Qt

Intervals are stored as an int number of milliseconds. There is no timer type, remainingTime() or callOnTimeout(), and interval properties cannot be bound. A timer must be started and stopped from the thread it lives in; the thread needs a running event loop.

Member Function Documentation

[explicit] QTimer::QTimer(QObject *parent = nullptr)

Constructs a timer with the given parent. The timer is not started.

[override] QTimer::~QTimer()

Destroys the timer. A running timer stops without emitting timeout().

int QTimer::interval() const

Returns the timeout interval in milliseconds. The default is 0.

See also setInterval() and intervalAsDuration().

std::chrono::milliseconds QTimer::intervalAsDuration() const

Returns the timeout interval as a std::chrono::milliseconds value.

See also interval().

bool QTimer::isActive() const

Returns true if the timer is running; otherwise returns false.

See also start() and stop().

bool QTimer::isSingleShot() const

Returns true if the timer stops after its first timeout. The default is false.

See also setSingleShot().

void QTimer::setInterval(int msec)

Sets the timeout interval to msec milliseconds.

If the timer is running it restarts, so the next timeout is a full interval from now.

See also interval() and start().

void QTimer::setInterval(std::chrono::milliseconds interval)

This is an overloaded function.

Sets the timeout interval to interval.

void QTimer::setSingleShot(bool singleShot)

Sets whether the timer stops after its first timeout. It does if singleShot is true; otherwise it repeats.

See also isSingleShot().

template <typename Func>[static] void QTimer::singleShot(int msec, Func &&functor)

Calls functor once, msec milliseconds from now.

The call is made from the event loop. It cannot be cancelled; use the context overload if the target may be destroyed first.

template <typename RecvT, typename Func>[static] void QTimer::singleShot(int msec, const RecvT *context, Func &&functor)

This is an overloaded function.

Calls functor once, msec milliseconds from now, unless context is destroyed first. The functor runs in the thread that context lives in, so this also runs it in another thread, as long as that thread has an event loop.

[slot] void QTimer::start()

Starts the timer with the current interval, or restarts it if it is already running. With a negative interval the timer does not start.

See also stop() and isActive().

[slot] void QTimer::start(int msec)

This is an overloaded function.

Sets the interval to msec milliseconds and starts the timer.

[slot] void QTimer::start(std::chrono::milliseconds interval)

This is an overloaded function.

Sets the interval to interval and starts the timer.

[slot] void QTimer::stop()

Stops the timer. Calling this on a stopped timer has no effect.

See also start() and isActive().

[signal] void QTimer::timeout()

This signal is emitted each time the timer's interval elapses. A single-shot timer is already stopped when the signal is emitted.

See also start() and setInterval().

int QTimer::timerId() const

Returns the identifier of the running timer, or 0 if it is not running.
