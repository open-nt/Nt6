# Agent Notes

## Project

Nt is a small, MIT-licensed, clean-room implementation of a subset of the
Qt 6 API (modules `NtCore`, `NtNetwork`, `NtSerialPort`, `NtDBus`, `NtSvg` and `NtTest`;
headers in `include/Qt*/`, sources in `src/`). Tools: `ntmoc` (a moc replacement)
and `ndoc` (the documentation generator). Source files start with
`// MIT License - see LICENSE`.

## Platform support

Nt should be cross-platform, targeting:

- Linux
- Android
- Windows
- macOS (OSX)

**Linux first, portability later.** Develop and validate on Linux now. Don't
add other-platform support prematurely, but avoid design choices that make it
hard later (e.g. keep platform-specific code isolated and prefer portable
C++/CMake constructs over Linux-only APIs where it costs little).

## Before every commit: `./check.sh`

`./check.sh` is the quality gate and **must pass before committing**; CI runs
the same script. `./check.sh --quick` skips the sanitizer build, and
`./check.sh --install-hook` installs a git pre-commit hook that runs it.
`./check.sh --fix` reformats changed lines with clang-format.

It checks, in order:

- file hygiene (no tabs, trailing whitespace or CRLF; every `.h`/`.cpp` starts
  with `// MIT License - see LICENSE`; public headers use `#pragma once`)
- no `TODO`, `FIXME`, `HACK` or `XXX` markers; use `TODO(#<issue>)` instead
- every `src/**/*.cpp` is listed once in `CMakeLists.txt`
- a Release build with `-Werror` (see `cmake/NtCompilerOptions.cmake`), and each
  public header compiling on its own
- all tests, and complete ndoc coverage (`--strict --require-complete`)
- clang-format on the lines you changed (`.clang-format`), clang-tidy on `src/`
  (`.clang-tidy`) and cppcheck (`.cppcheck-suppressions`)
- the tests again under AddressSanitizer and UBSan, and the thread and future tests under
  ThreadSanitizer (skipped if the toolchain has no TSan runtime and
  `NT_CHECK_ALLOW_MISSING=1` is set, or if TSan cannot start, as in unprivileged containers)

Fix findings rather than suppressing them. When a suppression is justified, keep
it narrow (`// NOLINT(<check>)` with a reason, or an entry with a comment in
`.cppcheck-suppressions`) and never disable a warning globally to get green.
New public API needs ndoc comments and tests in the same change.

## Build options

- `-DNT_WARNINGS_AS_ERRORS=ON` makes warnings errors (off by default so a newer
  compiler cannot break a consumer's build; `check.sh` turns it on).
- `-DNT_HARDENING=ON` (default) adds stack protector, `_FORTIFY_SOURCE`, CET and
  RELRO/now flags to optimised builds.
- `-DNT_SANITIZE="address;undefined"` (or `thread`) builds with sanitizers.
- A build without `CMAKE_BUILD_TYPE` defaults to Release.
- Use `qsizetype`/`std::size_t` consistently and cast explicitly; `-Wconversion`
  and `-Wsign-conversion` are on. Keep both `EAGAIN` and `EWOULDBLOCK` checks:
  they are equal on Linux but not on every platform.

## Meta-objects (ntmoc)

The libraries are processed by `ntmoc` like user code. A header in `include/Qt*/` that declares
`Q_OBJECT` or `Q_GADGET` gets a generated `moc_<header>.cpp` (see `nt_moc_library()` in
`cmake/NtMoc.cmake`), and the source file that implements the class must end with
`#include "moc_<header>.cpp"`. Including it keeps the meta-object in the same object file as the
class, so it is linked whenever the class is used from a static library. Declare properties with
`Q_PROPERTY`, enumerations with `Q_ENUM`, and give each class the signals and slots it has in Qt.

## Documentation (ndoc)

Reference documentation is generated by **ndoc** (`tools/ndoc`, full syntax in
`tools/ndoc/README.md`) from `/*! ... */` comments in the code. Configuration is
`doc/ndoc.conf`; the CMake `docs` target runs it with `--strict --require-complete`. Free-standing
pages live in `doc/*.h` (comment only, not part of the library).

Every public class and member must be documented. Run
`ndoc --require-complete doc/ndoc.conf` to list what is missing (also written to
`coverage.txt` in the output directory). The syntax is a subset of QDoc, so
write comments as you would in Qt.

### Rules

- Put a `/*! */` comment directly above the declaration or out-of-class
  definition (`.h` or `.cpp`). Class comments use `\class`.
- Start a function comment in the Qt style: "Returns ...", "Sets ... to
  \a value.", "Constructs ...", "Destroys ...".
- Refer to parameters with `\a name`; ndoc checks them against the declaration.
- Use `\c` for inline code, `\sa` for see-also, `\l{target}{label}` for links.
- Add `\since` for new API, `\overload` / `\reimp` where applicable, and
  `\internal` for anything that should not be documented.
- Every class gets a `\differences` ... `\enddifferences` block listing what
  differs from Qt (missing functions, narrower types, threading limits).
- Every enum `\value` must be described or `\omitvalue`d.
- Keep `\fn` signatures on one line. `*_p.h` files are not scanned.
- Examples go in `examples/` between `//! [tag]` markers and are included
  with `\snippet file tag`.

### Example

```cpp
/*!
    \class QTimer
    \brief The QTimer class provides repetitive and single-shot timers.

    A QTimer emits timeout() each time its interval elapses. Connect that
    signal to whatever should run, then call start():

    \code
    QTimer timer;
    QObject::connect(&timer, &QTimer::timeout, [] { poll(); });
    timer.start(250);
    \endcode

    \differences
    Intervals are stored as an \c int number of milliseconds. There is no
    timer type or \c remainingTime().
    \enddifferences

    \sa {Signals and Slots}
*/

/*!
    Constructs a timer with the given \a parent. The timer is not started.
*/
QTimer::QTimer(QObject *parent) : QObject(parent) {}

/*!
    Returns \c true if the timer is running; otherwise returns \c false.

    \sa start(), stop()
*/
bool QTimer::isActive() const { return m_id != 0; }
```
