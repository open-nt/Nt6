Detailed Description

A QMutex protects data that several threads access. A thread calls lock() before touching the data and unlock() afterwards; any other thread that calls lock() in the meantime blocks until the mutex is released. Prefer QMutexLocker, which unlocks the mutex automatically when it goes out of scope:

QMutex mutex;
int counter = 0;

void increment()
{
    QMutexLocker locker(&mutex);
    ++counter;
}

A QMutex is not recursive: locking it twice from the same thread without unlocking in between is undefined behavior. Use QRecursiveMutex when that is needed.

See also QMutexLocker, QRecursiveMutex, QReadWriteLock and QWaitCondition.

Differences from Qt

QMutex wraps std::timed_mutex. It has no RecursionMode constructor argument and no QDeadlineTimer overload of tryLock(). A negative timeout passed to tryLock() does not wait forever; it is treated as 0.

Member Function Documentation

QMutex::QMutex()

Constructs an unlocked mutex.

bool QMutex::isRecursive() const

Returns false; a QMutex is never recursive.

See also QRecursiveMutex.

void QMutex::lock()

Locks the mutex. If another thread holds the lock, this call blocks until the mutex becomes available.

See also unlock() and tryLock().

bool QMutex::try_lock()

Attempts to lock the mutex without blocking. Returns true if the lock was obtained; otherwise returns false. This is provided for use with std::lock and std::unique_lock.

See also tryLock().

bool QMutex::tryLock(int timeoutMs = 0)

Attempts to lock the mutex, waiting up to timeoutMs milliseconds for it to become available. Returns true if the lock was obtained; otherwise returns false.

If timeoutMs is 0 or negative, the call returns immediately.

See also lock() and unlock().

void QMutex::unlock()

Unlocks the mutex. The mutex must be locked by the calling thread.

See also lock().
