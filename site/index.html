The Qt 6 API you can ship anywhere, under MIT.

Nt is a small, clean-room implementation of the Qt 6 API. Keep your QObjects, signals and slots, CMake and tests. Link everything statically into one binary, from an arm64 board to a Cortex-M microcontroller, with no copyleft obligations.

#include <QCoreApplication>
#include <QTcpServer>
#include <QTimer>

int main(int argc, char *argv[])
{
    QCoreApplication app(argc, argv);

    QTcpServer server;
    server.listen(QHostAddress::Any, 7);  // echo

    QTimer heartbeat;
    QObject::connect(&heartbeat, &QTimer::timeout,
                     [] { qInfo() << "alive"; });
    heartbeat.start(1000);

    return app.exec();
}

Why Nt

Reasons teams choose Nt

Nt keeps the API your developers already know and removes the licensing and footprint questions that come with putting it in a product.

MIT license, statically linked

Every library is a static archive under the MIT license. Link it into closed firmware, ship one binary and keep the license notice. There is no relinking clause and no commercial seat to buy.

Read the license →

The Qt 6 API you know

Classes keep Qt's names and headers: QObject, QTimer, QTcpSocket, QWidget. Existing Qt code ports with a CMake change, and the docs list every difference from Qt.

Browse the API →

Microcontrollers with Zephyr

Nt Core and Nt Network build as a Zephyr module for Cortex-M class boards. The same event loop, timers, TCP and TLS run headless on an RTOS.

Nt on Zephyr →

Arm from day one

Release packages and the snap are built for amd64 and arm64, so the libraries and tools run on Raspberry Pi class boards, Jetson modules and Arm servers.

Modules Qt does not have

Nt Gamepad, Nt FM synthesis, Nt glTF and Nt GPIO extend the Qt API with what devices, games and kiosks need, in the same style and under the same license.

Embedded

From embedded Linux to a Cortex-M on Zephyr

Nt was built for devices. Static archives, no plugins to deploy and an MIT license make it simple to put the Qt API inside a product you sell.

  • Zephyr RTOS module. Turn on CONFIG_NT and link Nt::Core and Nt::Network. The QEMU sample on mps2/an385 passes JSON, timer, TCP, TLS and threading checks.
  • Small footprint. Core and Network link at about 920 KB of code for the NXP i.MX RT1170.
  • Static linking. One self-contained binary per target, with no shared Qt libraries to install or update on the device.
  • Hardware close at hand. Nt GPIO drives lines on the Linux GPIO character device or Zephyr; Nt Serial Port, Nt DBus and Nt Http Server cover the rest of a device's I/O.

Nt Only

Modules you won't find in Qt 6

Nt adds libraries in the Qt style for games, media and hardware. They follow the same naming, signals and documentation as the rest of the API.

Input

Nt Gamepad

Nt::Gamepad

Qt Gamepad from Qt 5, brought back: SDL GameControllerDB mappings, stable ids across replugging, dead zones, rumble and hot plugging.

 Audio

Nt FM

Nt::FM

Four-operator FM synthesis of game sound effects from patches of a few hundred bytes. Lock-free audio thread, with QML types in Nt::FMQml.

 3D

Nt glTF

Nt::Gltf

Loads glTF 2.0 scenes into meshes, PBR materials, textures, cameras and lights, ready for a Vulkan renderer or ray tracer.

 Hardware

Nt GPIO

Nt::Gpio

QGpioLine reads inputs with debounce and bias and drives outputs, on Linux 5.10 or later and on Zephyr.

Graphics

Vulkan, hardware ray tracing and NVIDIA DLSS

Nt GUI includes Qt's Vulkan classes, and the samples show how to drive the ray tracing pipeline from them.

  • Vulkan 1.0 to 1.3. QVulkanInstance, QVulkanWindow and the instance and device function tables. The loader is opened at run time, so programs still start where there is no Vulkan.
  • Ray tracing. Trace rays with VK_KHR_ray_tracing_pipeline from a QVulkanWindowRenderer.
  • ntgltfview. Shows a glTF 2.0 scene with ray traced shadows, reflections and glass, an HDR environment, and a camera you fly with the mouse, keyboard or an Nt Gamepad.
  • NVIDIA DLSS. ntgltfview can upscale with DLSS Super Resolution, from DLAA down to Performance mode.

DLSS uses NVIDIA's proprietary NGX SDK, which is not part of Nt. Configure ntgltfview with -DNT_DLSS_SDK_DIR to build it in; without it everything else works unchanged.

Get Nt

Install in one command

Nt is on the Snap Store for amd64 and arm64, in a signed apt repository for Ubuntu, and on the releases page as RPM and Arch packages. Or build it from source with CMake.

Get it from the Snap Store Install guide 
# amd64 and arm64, any Linux with snapd
sudo snap install open-nt6 --channel=candidate

# build against it
cmake -S . -B build \
  -DCMAKE_PREFIX_PATH=/snap/open-nt6/current/usr

Includes ntmoc, ntrcc, ndoc, the headers, static libraries and CMake package. snapcraft.io/open-nt6

# Ubuntu 22.04, 24.04 and 26.04
# add the signed repository (see the install guide), then:
sudo apt update
sudo apt install g++ cmake libnt6-dev nt6-tools

Headers go to /usr/include/nt6, so Nt can sit next to Qt. Add the repository

git clone https://github.com/open-nt/Nt6.git
cd Nt6
cmake -S . -B build
cmake --build build
sudo cmake --install build

# or vendor it: add_subdirectory(Nt6)

A build without CMAKE_BUILD_TYPE is a Release build with hardening flags on.

# prj.conf
CONFIG_CPP=y
CONFIG_STD_CPP17=y
CONFIG_NT=y
CONFIG_NT_NETWORK=y

# CMakeLists.txt
target_link_libraries(app PRIVATE Nt::Core Nt::Network)

Add Nt to your west manifest or ZEPHYR_EXTRA_MODULES. Zephyr guide
