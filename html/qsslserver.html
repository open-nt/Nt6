Detailed Description

Set a configuration holding a certificate and key, then use it like QTcpServer. newConnection() is emitted only for clients that finish the handshake, and nextPendingConnection() returns a socket that is already encrypted:

QSslConfiguration config = QSslConfiguration::defaultConfiguration();
config.setLocalCertificate(certificate);
config.setPrivateKey(key);

QSslServer server;
server.setSslConfiguration(config);
server.listen(QHostAddress::Any, 8443);
QObject::connect(&server, &QSslServer::newConnection, [&] {
    auto *client = static_cast<QSslSocket *>(server.nextPendingConnection());
    client->write("hello\n");
});

A client that does not finish its handshake within handshakeTimeout() is dropped, so a slow client cannot hold connections open indefinitely.

See also QSslSocket and QSslConfiguration.

Differences from Qt

The alertSent, alertReceived, peerVerifyError, preSharedKeyAuthenticationRequired and handshakeInterruptedOnError signals are absent.
