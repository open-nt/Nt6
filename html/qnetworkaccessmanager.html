Detailed Description

One manager is enough for a whole application. Each request returns a QNetworkReply straight away, and the transfer happens on the event loop:

QNetworkAccessManager manager;
QNetworkReply *reply = manager.get(QNetworkRequest(QUrl("http://example.com/")));
QObject::connect(reply, &QNetworkReply::finished, [reply] {
    if (reply->error() == QNetworkReply::NoError)
        qDebug() << reply->readAll();
    reply->deleteLater();
});

You own the reply: delete it with deleteLater() when finished() is emitted.

Redirects are followed by default, and credentials are not sent to a different origin. A response cut short reports RemoteHostClosedError rather than appearing to succeed.

See also QNetworkRequest, QNetworkReply and QUrl.

Differences from Qt

HTTP/1.1 only, over http: and https: (https needs a build with OpenSSL); ftp: and file: URLs fail with ProtocolUnknownError. Each request uses its own connection, with no keep-alive pooling. There is no cookie jar, proxy, cache, compressed-transfer support or authenticationRequired() signal; credentials in the URL are sent as HTTP Basic. A QIODevice body is read in full before the request starts, so uploads are not streamed.
