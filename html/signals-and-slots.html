Signals and Slots

How Nt objects notify each other without knowing about each other.

A signal is a member function an object emits when something happens. A slot is any function that runs in response. The sender does not know who is listening, which keeps classes independent.

Declaring Signals

Declare signals in a signals: section of a class marked Q_OBJECT. The ntmoc tool generates their bodies:

class Counter : public QObject {
    Q_OBJECT
public:
    void setValue(int value) { emit valueChanged(value); }
signals:
    void valueChanged(int value);
};

Connecting

Pass a pointer to the signal and a slot to QObject::connect(). A slot may be a member function or any callable, and may take fewer arguments than the signal:

QObject::connect(&counter, &Counter::valueChanged, &display, &Display::show);
QObject::connect(&counter, &Counter::valueChanged, [](int v) { log(v); });

Delivery

Connection type

Behaviour

Qt::DirectConnection

The slot runs immediately, inside the emit.

Qt::QueuedConnection

The arguments are copied and the slot runs from the event loop.

Qt::BlockingQueuedConnection

Like Qt::QueuedConnection, but the emitting thread waits until the slot has run.

Qt::AutoConnection

The default. Direct if the receiver lives in the emitting thread, queued otherwise.

Threads

Every object lives in a thread: the one that created it, or the one it was moved to with QObject::moveToThread(). That thread's event loop runs the object's timers and delivers its posted events and queued signals. Qt::AutoConnection compares the receiver's thread with the emitting thread each time the signal is emitted, so a signal emitted in a worker thread reaches a slot of an object in the main thread through the main thread's event loop:

auto *worker = new Worker;
worker->moveToThread(&thread);
QObject::connect(&thread, &QThread::finished, worker, &QObject::deleteLater);
QObject::connect(this, &Controller::start, worker, &Worker::run);   // queued
QObject::connect(worker, &Worker::result, this, &Controller::show); // queued
thread.start();

Connecting, disconnecting and emitting are safe from any thread. An object must be deleted from its own thread, or while its thread is not running events for it; use deleteLater() to delete an object in another thread.

String-based Connections

The SIGNAL() and SLOT() macros name a signal or slot by its signature, which lets you connect to members that you only know at run time. The class must have gone through ntmoc, which records its signals and slots:

QObject::connect(&counter, SIGNAL(valueChanged(int)), &display, SLOT(show(int)));

A connection that names a member that does not exist, or one whose arguments do not match, prints a warning and is not made. Signals that a class declares with a body of its own, and classes that ntmoc has not processed, can only be connected with the pointer-to-member syntax.

See also QTimer and QThread.
