Detailed Description

A value in JSON can be one of six basic types: a bool, a number, a string, an array, an object, or null. QJsonValue holds one of them, together with a seventh state, Undefined, which is what a lookup that finds nothing returns.

QJsonObject o = doc.object();
QJsonValue v = o.value("count");
if (v.isDouble())
    use(v.toInt());

Numbers are stored as either an exact integer or a double. Integers whose magnitude does not exceed 2^53 stay exact and are written without a decimal point; larger values and fractions are doubles. NaN and infinity cannot be represented in JSON, so they become null.

The accessor functions such as toString() and toInt() return a default value when the value has another type, and never convert between types. Values are copied cheaply: strings, arrays and objects are shared until they are modified.

See also QJsonObject, QJsonArray and QJsonDocument.

Differences from Qt

There are no constructors that take a QVariant, as in Qt 6; use fromVariant(). Overloads taking a C string key are provided for the operator[] functions of QJsonValue, QJsonObject and QJsonDocument, because QLatin1StringView converts implicitly in Nt, which would make a literal key ambiguous. A reference (QJsonValueRef) to an element that no longer exists reads as undefined instead of asserting.
